# 本地生成与公网发布的边界

## 默认：只生成本地网页

“做成HTML”不自动授权：创建公开仓库、开放服务器端口、建立隧道、上传所有研究文件、购买域名或更改账号配置。脚本不联网、不读取凭据、不调用部署服务，生成后状态仍是local-only。

只需打开本地页面时，无需账号，也无需为此安装托管工具。不要把localhost/file URL说成别人可访问的公网链接。

## 用户明确要公网URL时

先确认四件事，再调用对应平台的实际工具：

1. 托管目标：已有网站/仓库/静态托管账号，或用户明确选择的新目标。
2. 发布范围：主报告、内部审校/笔记、原稿下载和附件哪些允许公开。即使用户要求公开主报告，也不能自动包括整个父目录。
3. 内容与许可：检查个人路径、凭据、未公开材料；原论文PDF/图片可能另有再分发许可，优先考虑链接原站而非默认上传。
4. 版本策略：新URL/新版本，还是覆盖已发布版本；需要时准备可回退的旧版本。

没有账号授权时，把已验证的静态目录交付给用户，说明远端阻塞。不要从聊天接收token，不要把凭据写入网页、manifest或仓库。不要自动安装/授权其他MCP或修改别的profile。

## 部署后必须真实验证

- 读取完整线上入口URL，确认不是登录页、404、旧版本或占位页。
- 检查中文编码、CSS/JS、本地相对资源、引用锚点、至少一个附页或附件。
- 验证子路径部署：例如站点挂在 `/research/report/` 时，相对链接仍应正常。
- 记录最终URL、验证时间和仍未验证的项目。部署API成功并不等于读者已能访问。
- 不要因网站上线而声称论文结论已独立复现；页面仍需保留原研究报告的证据边界。

## 不是本skill的职责

研究论文全文分析属于paper-reader/critic/synthesizer链；画新图属于doc-diagram-orchestrator；知识库事实更新属于maintainer/updater。这里负责保真呈现与可验证交付，不在排版时改变研究结论。
